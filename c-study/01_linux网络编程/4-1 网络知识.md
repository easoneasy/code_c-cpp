
##### http
超文本传输协议
客户端和服务器之间传输超文本数据

###### http请求报文
包含四个组成部分：请求行、请求头、空行、请求体（正文）。
```
请求行、请求头、空行、请求体（请求正文）
(1)请求行 get  /  HTTP/1.1
请求方法（get、post）  URL  协议类型

(2)请求头
Connection:keep-alive 长连接；
Cookies：       无状态

(3)空行

(4)请求正文  如果请求方法是get，那么请求正文可以是空的，但是其他请求方法的时候，不为空
```

**1、请求行**
包含三部分：请求方法、请求资源、请求协议

1）请求方法：get、post。
GET主要用来进行查询数据，
POST主要用来进行提交数据 。
get会将请求的内容放在地址栏中，但是post会将内容放在请求体中。
==get和post的区别（重点）==
2）请求资源
URL：统一资源定位符，就是在网络上定位一个资源（网页、图片、视频）
3）请求协议
现在基本使用的是http的1.1版本

**2、请求头**
里面可能会包含很多字段，比如：Connection（连接，可以有值keep-alive）、Referer（记录上一个跳转的网页）

**3、空行**
主要为了去讲请求头与请求正文分开。

**4、请求正文**
客户端向服务器请求的数据，特别注意：get请求的请求正文是可以为空的，其他的请求一般是不为空的。

###### http的响应报文

包含四部分：响应行、响应头、空行、响应体（响应正文）
```
响应行、响应头、空行、响应体（响应正文）；
(1)响应行  HTTP/1.1  200 OK
 协议   状态码  原因短语
(2)响应头
(3)空行
(4)响应体
```
**1)响应行**

响应行包含三部分：协议类型、状态码、原因短语。
-协议类型
使用的协议，http以及使用的版本1.1。（因为现在基本常用的是1.1，所以这个协议基本就定死了）

-状态码
1xx：100字段。已经被废弃了，基本不用。
2xx：200字段。表示请求成功/正常；
3xx：300字段。重定向（bing.com）
4xx：400字段。表示请求包含语法错误或无法完成，也说明服务器资源不存在(但是服务器是存在的)
5xx：500字段。服务器异常，服务器在处理请求的过程中发生了错误

-原因短语
对状态码进行解释，主要是给人看的

**2)响应头**
里面也会包含很多字段，但是不同的浏览器、或者不同的厂商可能会自己加一些自己的字段。

**3)空行**
将响应头与响应体（正文）分隔开来

**4)响应体**
服务器向客户端返回的数据

###### http的特征
是可靠的（传输层使用的是TCP协议）
http1.1的版本使用的是长连接，
但是1.0版本使用的是短连接。

http的1.0、1.1、2.0的版本都使用的是TCP协议，主要对比1.0与1.1,其中1.1是长连接（三次握手之后会重复利用这个连接），
1.0是短连接（每一次的数据传输都需要三次握手），所以从这一点来说，1.1版本比1.0版本的效率要高一些；

http连接是一个无状态的、明文传输（不安全，容易被篡改、被攻击）

http与https的区别
https使用的是密文传输，会使用证书以及加密方式进行加密，而加密方式有对称加密也有非对称加密。

对称加密 123------>124------->123

非对称加密：使用公钥、私钥。用公钥加密的密文需要私钥进行解密。

##### TCP协议
TCP是传输层的协议，是可靠传输（三次握手、四次挥手、确认机制）、面向连接的、全双工。

##### UDP协议的特点

UDP也是传输层协议，是一个无连接的、不可靠的、无拥塞控制、传输速率快、开销小。
