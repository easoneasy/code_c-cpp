
互斥锁是全局变量，只有两种状态，未锁与已锁
任意时刻只能有一个线程能上锁成功
谁上锁就需要谁解锁
互斥锁要成对出现，只上锁不解锁会导致一直处于锁定状态
一个线程连续两次以上的上锁，第二次会导致死锁
一次上锁，两次解锁，程序不会卡住，会报资源或设备忙的异常

###### 锁的使用
锁的类型`pthread_mutex_t`

锁的初始化
动态初始化:
```c
int pthread_mutex_init(
// 要初始化的锁
    pthread_mutex_t *mutex, 
// 锁的属性类型
    const pthread_mutexattr_t *attr 
);
```
静态初始化
```c
pthread_mutex_t mLock = PTHREAD_MUTEX_INITIALIZER;
```
加锁：
```c
int pthread_mutex_lock(
    pthread_mutex_t *mutex //锁
);
```

解锁：
```c
int pthread_mutex_unlock(
    pthread_mutex_t *mutex //锁
);
```

销毁锁
```c
int pthread_mutex_destroy(
    pthread_mutex_t *mutex // 锁
);
```


死锁：线程在执行过程中，由于竞争资源使用不当造成的永久阻塞的现象
（1）某个线程连续两次以上的加锁，会导致死锁
（2）某个线程持有锁之后，在没有解锁之前就终止，会导致死锁
（3）A与B两个线程，A线程获取1锁，B获取2锁，A线程还想获取B线程的2锁，但是B线程又不释放2锁，这时由于资源推进不当也会导致死锁


pthread_mutex_trylock
获取互斥锁和加锁时，是非阻塞锁


自旋锁
导致cpu效率低

读写锁
读是共享的，多个线程都可以对共享资源加读锁，写是排它的，只要有写操作，其他的写都不能进行，除非写被释放了。
读共享、写排它


条件变量
pthread_cond_wait
线程在不满足共享资源的某个条件时等待/挂起，直到另一个线程发出通知，告诉它条件已满足，进一步唤醒这个等待。
不满足条件就睡觉，等条件成立让另一个线程将睡觉的线程唤醒
//重要
（1）如果该函数要睡眠的时候，需要将获取的锁在睡眠之前解锁，这个过程中解锁与睡眠是原子的
（2）被唤醒，然后抢锁，最后从函数上返回（抢到锁就返回，抢不到锁就不返回）


条件变量的数据类型`pthread_cond_t`

POSIX在实现的时候，允许唤醒一个以上的线程


pthread_cond_signal只唤醒一个
pthread_cond_broadcast全部唤醒


###### ==虚假唤醒==
面试常考、重点
如果多个线程在条件变量上睡觉，假如多个线程都被唤醒只有少数线程执行的时候就可以完成任务，其他被唤醒的线程不需要执行任务，所有其他被唤醒但没有执行任务的线程可以认为是无效唤醒（不需要唤醒）称为虚假唤醒
解决方法：睡眠的线程即使被唤醒了，甚至抢到了锁返回了，继续让该线程检测条件是否满足，如果满足就继续睡觉，否则就向下执行，达到真正唤醒之后的事情。
这个改法就是将if--->while
```c
while(condtion ==true){
	pthread_cond_wait;
}
```
