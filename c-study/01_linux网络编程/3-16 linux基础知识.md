文件系统与目录系统调用填空题
在 Linux 中，万物皆文件。要获取一个文件的元数据（如大小、权限、inode 号等）而不打开文件，最常用的系统调用是  stat
struct stat 结构体中的 st_mode; 成员是一个 16 位的位图，它同时包含了 文件类型 和 访问权限 信息。

要判断一个文件是否为“目录”，可以使用内核提供的宏 S_ISDIR(st_mode)

在处理权限时，若要提取出所有者、所属组和其他人的 rwx 权限，通常需要将 st_mode 与掩码 07777 _ 进行按位与（&）运算。

目录文件在逻辑上可以看作一张表，其条目被称为 dirent（目录项），每个条目至少包含文件名和 inode 编号。

opendir 函数返回的是一个指向 DIR 类型的指针，它被称为目录流句柄，类似于文件编程中的 FILE 。

每调用一次 readdir 函数，目录流的指针就会向后移动一个位置，返回下一个目录项的信息。

当 readdir 返回 NULL 时，通常意味着已经读取到了目录的 末尾/发生错误。

在实现 ls -a 时，程序必须能够处理两个特殊的目录项：代表当前目录的 . 和代表 上一级目录 的 ..。

修改当前进程的工作目录（相当于在终端执行 cd 命令），对应的系统调用函数是 chdir

系统编程基础与学习方法填空题
一、 标准与概念（ISO-C vs POSIX）
ISO-C 被称为标准 C，而 POSIX-C 是主要在 类unix 环境下有效的标准。

在通用性方面，ISO-C 的通用性更强，几乎所有现代操作系统都支持它。

ls -al 或 cp 等 Shell 命令，本质上也是通过调用 系统调用 来完成任务的。

学习顺序建议先从 文件系统编程 开始，因为在 Linux 中，“一切皆文件”，掌握了文件操作，后续的进程、网络等操作都是相通的。

二、 函数学习与 man 手册
学习系统编程函数时，不建议强行记忆所有参数，而应重点记住 函数名 和 _声明。

在使用 man 手册查询时，第 2 卷对应的是系统调用，第 3_ 卷对应的是库函数。

如果忘记了函数的头文件或声明，应该通过 man 手册查看 SYNOPSIS___概述_ 部分。

三、 返回值与错误处理逻辑
C 语言没有专门的错误处理机制，通常通过 返回值 来告知调用者是否出错。

对于返回基本数据类型的函数，通常返回 -1 表示出错；此时系统会将具体错误码存入 errno 变量中，可以使用 perror() 打印信息。

对于返回指针类型的函数（如 malloc），调用失败时通常返回 NULL。

四、 参数理解（见名知意）
在函数声明中，如果指针参数带有 const 修饰（如 const char str），意味着该参数是 只读 的，主要负责将信息传入函数。

如果指针参数 没有 const 修饰，说明该参数承担了 _传入传出 的任务，函数可能会修改它指向的内容。

对于没有 const 修饰的指针参数，传入的指针必须指向 堆/栈上的可写内存，否则程序运行时会报错。

一、 洞察类型别名（Type Aliases）
在 Linux 开发中，很多类型（如 mode_t, off_t）本质上都是类型别名。要查看它们的真实原始类型，建议使用 gcc 的 -E___ 选项进行预处理。

执行 gcc -E test.c -o test.i 后，所有的头文件内容会被展开到 test.i 中，此时可以使用 grep 命令结合 -nE 参数快速搜索关键字所在的行号。

在使用 grep 搜索结构体定义（如 struct stat）时，建议加上 -A 参数，以便同时显示匹配行前后的内容，方便观察结构体成员。

在 vim 查看预处理文件时，按下 n 键可以向下跳转到下一个搜索匹配项，按下 N 键则跳转到上一个。

二、 目录相关系统调用
函数 int chmod(const char pathname, mode_t mode); 中，参数 mode 的类型 mode_t 实际上是一个 无符号整数（填数据类型方向），用于表示文件的访问权限。

改变当前进程的工作目录（类似于 Shell 中的 cd）应使用系统调用 chdir。

getcwd 函数的作用是 获取当前工作目录的绝对路径。

mkdir 用于创建目录，而 rmdir 只能用于删除 空 目录。

三、 学习技巧与工具使用
当你忘记了函数的具体形参定义时，除了查阅 man 手册，还可以利用 IDE 或编辑器的提示功能，或者将 man 手册的函数声明部分钉在屏幕上作为参考。

通过查看函数声明中形参的 类型，往往能直接猜出该参数的含义（如 pathname 代表路径，mode 代表模式/权限）。
