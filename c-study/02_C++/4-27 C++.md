
##### 命名空间
命名空间 ：避免名字冲突的机制
主要作用：区分同名实体

使用方式：
	1、使用作用域限定符 `命名空间名字 :: 实体`
	2、使用using编译指令 `using namespace 命名空间名`
	3、使用using声明机制 `using 命名空间名 :: 实体` （用哪个声明哪个）

- uisng编译指令使用命名空间实体，命名空间实体不能与全局实体同名
- 同一作用域内用using声明机制，不同的命名空间的实体，不能是同名的，否则会冲突

特殊的命名空间
1、嵌套
	在一个命名空间中再建命名空间
	访问明明空间的实体
		先访问外部的命名空间，再访问里面的命名空间
可以跨模块使用

2、匿名
	可以直接访问
	作用域限定符   ` :: + 命名空间中的实体`
不可以跨模块使用

##### const

const  vs  宏
发生时机不同
	宏是预处理阶段
	const 是编译时
是否检查安全
	宏没有类型检查，单纯的**文本替换**
	const 有类型检查

const   修饰变量 -->类似 常量  （只有只读属性）

const  与  *  的位置  指谁谁不动
const修饰指针类型
1、指向常量的指针 pointer to constant 
	const 在 * 左边   `const int *p`   `int const *p`
	不能通过指针的指向  来 修改数据，但是可以修改指针的指向
2、指针常量 constant pointer
	const  在 * 右边  `int * const p`
	可以修改指针数据，不能修改指针的指向

变量本身是个常量 ： const int num =1; 
- 不能使用普通指针指向num 需要使用带const的指针 const int  * p
`const int *p = &num ;`

`int (* s[10])(int) `  函数指针数组
s先跟数组结合，再是指针

##### 引用
一个已经存在的 变量或对象 的别名
`数据类型 & 引用名 = 变量/对象`
引用的本质是一个特殊的指针（常量指针，指向不能修改）
引用一经绑定就不能修改
```c++
//num是本体
int num = 1;
//ref是别名，可以操纵别名，影响本体
int & ref =num;
ref = 2;
//num的值会发生变化  num = 2

```

**引用和指针的区别**
本质都是指针，都可以间接访问
不同点：
引用定义的时候必须要初始化
指针可以只声明，不初始化
引用取地址 是   取的所绑定变量的地址
指针取地址 是   指针变量的地址

**引用的使用场景**
希望在函数内部进行函数参数的交换
形参的交换   ----->  影响实参的交换

引用传递，可以起到和指针一样的效果，比指针使用简单，并且不会复制

return 会进行复制操作，不想复制可以使用引用
```c++
int gNum = 100;
//返回值类型为int&，return时不会进行数据复制
int & fun3(){
	return gNum;
}

//不要返回一个局部变量的引用
int & fun4(){
	//局部变量，生命周期问题
	int a = 10;
	return a;
}
int & ref = fun4();
//定义一个ref的引用，绑定了一个fun4()的函数
//fun4()已经执行完毕，生命周期结束
//赋值给引用会出现段错误
//打印ref会出现段错误

//函数返回堆空间的变量需要使用指针接收，再释放堆空间，否则会出现内存泄漏

int num = 1;
const int & ref = num;
//ref = 2;   //error
//常引用：
//不希望通过函数的形参 修改实参的数据
const int & ref = num;
```

##### 函数重载
同一作用域内，函数名相同，**形参列表不同**，功能类似的一组函数
可以通过函数**参数的个数**、**参数的类型**、**参数的位置** 区分

函数的重载和返回值没有关系

**函数重载的原理**：名字改编机制 name mangling 

可能会存在二义性问题ambigious
```c++
void print3(int a,double b){

}
void print3(double a, int b){
}

void test(){
	print3(100,100);  //error  二义性问题
	//两个print函数都可以使用int型，编译器不知道选择哪一个
}
```

```c++
}
```

##### 内联函数
了解
inline函数：内联函数
为了替代宏，使用函数体来替代函数调用

什么情况下适合内联函数，什么情况下不适合
1、函数体比较简短、逻辑简单，适合内联
2、函数中有递归调用、嵌套循环，不适合内联

宏函数
```c++
#define MAX(a,b)  (a) > (b) ? (a) : (b)
int result = MAX(20,10) + 20;   -->20
int result = MAX(10,20) + 20;   -->40
```

使用 inline  函数 修饰普通函数
```c++
//像编译器发出内联建议，但编译器不一定采纳
inline 
int getMax(int a ,int b ){
	return a > b ? a : b ;
}
-------------------------------------
//内联函数  声明和实现分开写
//在一个函数体中
inline void print();  //声明
inline void print(){}  //实现

//头文件.hpp 和.cc 分开

//把实现文件包含到头文件中
//把实现的内容写在头文件中
```

宏函数   vs   内联函数
**发生的时机不一样** ，宏函数：==预处理==，内联函数：==编译阶段==
**是否方便调试**，宏函数不能调试，内联函数可以调试
类型安全： 宏函数没有类型检查，内联函数有类型检查

##### 异常处理
了解
描述程序中的错误
有可能不止是程序的问题，网络问题也会，比如注册的时候输入的不符合预期

关键字：
	try：代码块，包裹可能出现异常的代码
	catch：捕获异常，对异常进行处理
	throw：抛出异常信息
异常行下面的代码不执行
可以有很多catch，从上到下依次匹配
只有try有异常，才能捕捉到catch、throw

```c++
try{
//可能出现异常的代码
}catch(异常的类型){  //可以有好几个异常/异常的类型不同
//每次执行一个catch，执行哪个取决于接收的类型
//处理异常信息
}

throw "错误信息。字符串类型";
throw 0 //抛出整型
```

另一种使用场景，作为函数的一个特殊的返回结果
```c++
int func (int arr[],int index){
	if(index <0 || index >= size){
		throw "index is illegal";  //返回异常结果
	}
	return arr[index];
}
```
