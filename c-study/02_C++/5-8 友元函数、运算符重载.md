##### 友元
作用：破除私有限制，访问类的私有成员
普通函数的友元形式：友元函数
成员函数的友元形式：把成员函数声明为友元
友元类：把类声明为友元

特点：
	单向的
	破坏了封装性
	不具备传递性
	不能被继承

```c++
class Myclass
{
public:
	//可以把普通函数设置为友元
	//可以放在public 也可以private里
	friend void test1();
private:
	int m_data = 1;
};
//void test1()就可以直接访问private的变量

```

在一个类中访问另一个类的私有成员
```c++
class FriendClass
{
	
};
```

把一个类变成友元
```c++
//友元类
friend class Myclass
```

##### 运算符重载

本质：函数调用

不能被重载的运算符
- `.` 成员访问运算符
- `.*`成员指针访问运算符
- `?:`三目运算符
- `::`作用域限定符
- `sizeof`长度运算符
 **所有带点的运算符、sizeof不能重载**

运算符重载的形式：
	友元函数：不修改操作数的值的运算符
	成员函数：修改操作数的值

重载一个运算符时，需要考虑：
	采用什么形式：普通函数/成员函数
	函数的返回值：有无、类型
	函数的参数：有无、几个、类型
	函数体的代码逻辑应该怎么写，和运算符本身的逻辑一致

什么情况下进行运算符重载？
	只有自定义类型才能做运算符的重载
	能为自己的类（Class）或结构体（Struct）定义符合业务逻辑的操作符
内置类型可以重载吗？
	C++ 不允许改变 `int`、`double`等内置类型原有的运算符行为

一个自定义类型用到另一个自定义类型
两个类都要进行重载

函数指针
```c++
func1();
//简写
void (*f)() = func1();
f();   //调用func1
//完整写法
f = &func1;
//对函数指针解引用，得到函数名，调用func1
(*f)();

//定义别名
//定义一种类型F，返回值为void，形参列表为空的函数指针
//可以用F表示
typedef void (*F)();
F ff = &func1;
ff();

//C++11之后的别名可以用using
using FFF = void(*)();
FFF fff = &func1;
```

**成员函数调用**
```c++
FFF obj;
obj.f1();
//使用类名作用域的方式
//对于成员函数指针来说需要完整写法
void (FFF::*f)()=&FFF::f1;
//成员函数的调用依赖对象
(obj.*f)(); //调用f1函数

FFF *p = obj;
p->f1();    //和obj.f1()等价
(p->*f)();  //调用f1函数
```

可以通过空指针调用成员函数，但是无法访问数据成员（依赖对象）

嵌套类
把一个类定义在另一个类中
作用：
内部类为外部类提供服务，并且对外界进行隐藏内部类
```c++
//外部类
class Outer
{
	//内部类
	class Inner
	{
	
	};
public:

};
```

嵌套类的访问规则
- **在外部类的外部访问内部类的成员**
	public的内部类，可以创建内部类对象，通过对象.访问，public的成员可以访问，private不行， 使用友元 ，访问谁在谁内部设置友元
	private的内部类，不能直接创建对象，没有权限，除非使用友元，然后再通过对象.方式访问，public的成员可以访问，private不行，除非使用友元
- **在外部类的内部访问内部类的成员**
	创建对象，通过对象.的方式访问内部类成员，public ok，private no，除非使用友元
	修饰内部类的权限是public或private没有意义，都可以创建对象
- **在内部类的内部访问外部类的成员**
	无论外部类的成员是什么权限，内部类都可以访问

静态单例
方式一：
利用栈对象的生命周期自动释放资源
把单例对象作为资源。交给另一个对象来管理

- 把静态单例的资源清理函数放在管理者对象的析构函数中

方式二：
利用嵌套类+静态的内部类对象
- 将管理者设置为内部类，把单例的资源清理函数放在管理者的析构函数中

方式三：
利用atexit() + destoryInstance()

- 将资源清理函数放在atexit中注册（只注册一次）
- 放在创建单例对象的语句中
atexit
回调函数
在程序结束时，自动调用已注册的函数
执行顺序：先注册的后调用执行
同一个函数：可以多次注册，会多次调用

方式四：
利用atexit() + destoryInstance() + pthread_once  线程安全的
