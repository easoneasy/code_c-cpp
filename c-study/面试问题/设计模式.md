
##### 工厂模式
核心思想：把对象创建和对象使用分离
工厂模式配合unique_ptr
```
工厂创建对象
    ↓
调用者独占对象

符合
unique_ptr
=
独占所有权
```
离开作用域：自动析构、自动释放

什么是工厂模式？
```
工厂模式是一种创建型设计模式，其核心思想是将对象的创建过程封装到工厂类中，实现对象创建与对象使用分离。
客户端不直接通过new创建对象，而是通过工厂接口获取对象，从而降低代码耦合度，提高扩展性和维护性。
```

工厂模式有什么优点？
```
1. 封装对象创建过程

2. 降低耦合

3. 便于扩展

4. 统一管理对象生命周期
```

工厂模式和智能指针怎么结合？
```
现代C++通常让工厂返回 unique_ptr<Base>
由调用者独占对象所有权，避免手动delete，同时满足RAII原则。
```

工厂模式和多态的区别？
```
多态解决的是对象使用的问题，通过基类指针调用派生类实现；

工厂模式解决的是对象创建的问题，将new操作封装起来。
实际项目中二者通常配合使用：工厂负责创建具体派生类对象，多态负责统一使用这些对象。
```

引入工厂模式
```c++
#include <iostream>
#include <memory>

using namespace std;

class Shape
{
public:
    virtual void draw() = 0;

    virtual ~Shape() = default;
};

class Circle : public Shape
{
public:
    void draw() override
    {
        cout << "draw Circle" << endl;
    }
};

class Rectangle : public Shape
{
public:
    void draw() override
    {
        cout << "draw Rectangle" << endl;
    }
};

class ShapeFactory
{
public:
    static unique_ptr<Shape>
    createShape(int type)
    {
        if(type == 1)
        {
            return make_unique<Circle>();
        }

        if(type == 2)
        {
            return make_unique<Rectangle>();
        }

        return nullptr;
    }
};
```

客户端只需调用createShape
```c++
int main()
{
    int type;
    cin >> type;
    auto shape = ShapeFactory::createShape(type);
    if(shape)
    {
        shape->draw();
    }
    return 0;
}
```

##### 观察者模式
```
一个对象变化
↓
通知多个对象
```

```
       Subject
           |
     ----------------
     |      |       |
 Observer Observer Observer
```
==subject不拥有observer==
只是知道它的存在 --> 可以使用weak_ptr
observer自己管理生命周期
subject只观察

观察者接口
```C++
class Observer
{
public:
    virtual void update() = 0;

    virtual ~Observer() = default;
};
```

具体观察者：
```c++
class User : public Observer
{
public:
    void update() override
    {
        cout << "收到通知" << endl;
    }
};
```

被观察者：
```c++
class Subject
{
private:
    vector<weak_ptr<Observer>> observers;

public:
    void addObserver(
        const shared_ptr<Observer>& ob)
    {
        observers.push_back(ob);
    }

    void notify()
    {
        for(auto it = observers.begin();
            it != observers.end();)
        {
            if(auto ob = it->lock())
            {
                ob->update();
                ++it;
            }
            else
            {
                it = observers.erase(it);
            }
        }
    }
};
```

使用：
```c++
Subject stock;

User u1;
User u2;

stock.addObserver(&u1);
stock.addObserver(&u2);

stock.notify();

//输出
//收到通知
//收到通知
```

> 为什么观察者模式通常使用 weak_ptr？

> 因为 Subject 只是观察 Observer，而不拥有 Observer。
> 使用 weak_ptr 可以避免保存已经失效的裸指针，同时不会增加引用计数、不会延长 Observer 的生命周期。
> 通知时通过 lock() 判断对象是否仍然存在，从而安全地访问对象。

weak_ptr 的本质作用是“引用一个对象，但不拥有这个对象”，因此既能避免野指针，又不会影响对象生命周期。


##### 单例模式
核心目标：保证一个类在整个程序中只有一个对象，并很多地方都要访问它
使用场景：
	日志系统
	配置中心
	线程池
	数据库连接池
这些对象通常管理共享资源，创建多个实例会导致状态不一致或资源浪费



单例设计模式的实现步骤:
	1.private修饰构造函数(构造函数私有)
	2.提供一个public static函数返回这个唯一的对象
	3.在函数中保证该对象唯一
通常可以把拷贝构造,赋值运算符删掉


静态单例
单例对象创建在静态区
```c++
class Singleton
{
public:
    static Singleton & getInstance()
    {
        static Singleton instance;
        // 返回一个唯一的对象
        return instance;
    }
    // 删除复制控制的函数
    Singleton(const Singleton &) = delete;
    Singleton& operator=(const Singleton &) = delete;
private:
    Singleton(){}
};
void test1()
{
    cout << &Singleton::getInstance() << endl;

    cout << &Singleton::getInstance() << endl;

    cout << &Singleton::getInstance() << endl;
}
```

堆上单例
线程不安全
步骤:
	1.构造函数私有
	2.提供一个外部的访问入口public static获取这个唯一的对象
	3.函数中保证这个对象是唯一的
	4.提供一个自身类型的satic指针

```c++
class Singleton
{
public:
    //假设有2个线程 A B
    static Singleton * getInstance()
    {
        //假设A线程先执行 
        //B线程执行
        // 增加一些逻辑判断
        if(!m_pInstance){
            // A线程进入到if中 但是还没来得及new对象
            // 发生了线程切换 切换到B线程
            // B线程也进入到if中
            m_pInstance = new Singleton{};
        }
        return m_pInstance;
    }
    
    // 释放资源的操作
    static void destroyInstance()
    {
        if(m_pInstance){
            delete m_pInstance;
            m_pInstance = nullptr;
        }
    }
    // 删除复制控制相关的函数
    Singleton(const Singleton &) = delete;
    Singleton& operator=(const Singleton &) = delete;
private:
    Singleton(){}
    // 增加一个自身类型的指针
    static Singleton * m_pInstance;
};

// 类外初始化
Singleton * Singleton::m_pInstance = nullptr;

void test1()
{
    cout << Singleton::getInstance() <<endl;
    cout << Singleton::getInstance() <<endl;
    cout << Singleton::getInstance() <<endl;
    Singleton::destroyInstance();
}
```

单例模式哪些线程安全实现？
1、互斥锁，保护对象创建过程
	缺点：每次获取实例都要加锁，性能较差
2、双重检查锁，减少锁开销
3、局部静态对象，C++11局部静态变量初始化线程安全
	保证只初始化一次
```
C++11标准规定，函数内部局部静态变量的初始化具有线程安全保证。当多个线程首次同时进入该函数时，标准库会保证只有一个线程执行初始化，其余线程会等待初始化完成，因此对象只会构造一次。
```


饿汉式：
	程序启动，对象立即创建
```
优点：
	实现简单，天然线程安全
缺点：
	提前创建，若一次都没用到会导致浪费资源
```

懒汉式：
	第一次使用，才创建对象，以后再使用直接返回
```
优点：
	按需创建
缺点：
	C++11之前具有线程安全的问题，需要加锁
	C++11之后局部静态变量初始化线程安全
```
