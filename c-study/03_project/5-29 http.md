http事务
http请求---http响应

URI：统一资源标识符，标识web上的资源
用作http请求的目标，代表请求资源的位置
常见的类型：URL（统一资源定位符）网址

URL由五部分组成：方案scheme、主机信息authority、路径path
查询参数Query、片段Fragment

```
<scheme>://<authority><path>?<query>#<fragment>
authority可细分为:
<username>:<password>@<host>:<port>
```


常见的请求方法有哪些？它们的作用是什么？各有什么特点？
核心4种方法：
GET：获取资源
- 作用：向服务器请求指定的资源，只用于获取/查询数据，不应该对服务器数据产生任何副作用
```
特点：
参数位置：参数附加在 URL 后面（如 /search?q=keyword），暴露在地址栏中。

数据大小：受浏览器和服务器对 URL 长度的限制（通常几 KB）。

安全性/幂等性：具有安全（不修改数据）和幂等（连续请求多次，结果和副作用相同）的特性。

缓存：请求结果可以被浏览器缓存、历史记录留存。
```

POST：传输/创建资源
作用：向指定资源提交数据，通常用于创建新资源/提交表单（用户注册/上传文件）
```
特点：
参数位置：参数放在 HTTP 请求的 Body（请求体） 中，不会显示在 URL 中。

数据大小：原理上没有限制，适合传输大文件或大量数据。

安全性/幂等性：不安全且不幂等。连续提交两次 POST 请求，服务器通常会创建两条重复的数据（比如生成两个订单）。

缓存：默认不会被缓存
```

PUT：更新资源（完整替换）
作用：向指定资源位置上传最新内容，通常用于修改/更新已有资源
```
覆盖性：它是完整替换。如果你只想修改用户的年龄，但使用 PUT 且未传别的数据，可能会导致其他字段被置空。

安全性/幂等性：不安全（修改了数据），但具有幂等性。因为无论你用同一份数据 PUT 覆盖多少次，资源最终的状态都是一样的。
```

DELETE：删除资源
作用：请求服务器删除指定的资源
```
安全性/幂等性：不安全（删除了数据），但具有幂等性。第一次删除成功后，资源就没了，后面再请求删除同一个资源，虽然返回的状态码可能不同（如 404），但系统资源的状态不再会改变。
```


响应状态码分为哪几类？每类都有哪些常见的状态码？它们的含义分别是什么？

分为5类

- 1xx 信息性状态码（较少遇到）
这类状态码表示请求已被接受，需要继续处理。
```
101 Switching Protocols (切换协议)：服务器根据客户端的请求切换协议。例如，浏览器尝试升级到 WebSocket 协议时，服务器如果同意会返回 101。
```

- 2xx 成功状态码（皆大欢喜）
表示请求成功并被正确处理。
```
200 OK：最常见的成功状态码。表示从客户端发来的请求在服务器端被正常处理了，响应体中包含请求的数据。

201 Created：请求成功且服务器创建了新的资源。通常在 POST 请求成功创建新用户或新订单时返回。

204 No Content：请求成功，但响应报文不包含主体部分。通常用于不需要向客户端返回任何新数据的情况（如删除成功的 DELETE 请求）。
```

- 3xx 重定向状态码（换个地方找）
表示资源位置发生了变动，浏览器需要自动发起新的请求到新地址。
```
301 Moved Permanently (永久重定向)：请求的资源已被永久分配了新的 URL。浏览器以后会自动访问新 URL，搜索引擎也会更新权重。常用于网站换域名。

302 Found (临时重定向)：请求的资源临时分配了新的 URL。这次请求用新 URL，但由于是临时的，浏览器下次还会访问原 URL。

304 Not Modified (未修改)：非常重要。 客户端发送附带条件的请求（带有缓存检查字段）时，服务器端允许请求访问资源，但因资源未改变，直接让浏览器去读本地缓存，从而节约带宽。
```


- 4xx 客户端错误状态码（前端/用户的锅）
表示问题出在客户端，比如参数写错、地址写错或没权限。
```
400 Bad Request：客户端请求有语法错误或参数格式不正确，服务器无法理解。

401 Unauthorized：表示该请求需要用户的身份认证（未登录或 Token 失效）。

403 Forbidden：服务器理解请求，但拒绝执行。通常因为你虽然登录了，但没有访问该资源的权限（比如普通用户尝试访问管理员后台）。

404 Not Found：极其常见。服务器上找不到请求的资源（通常是 URL 打错了或资源被删除了）。

405 Method Not Allowed：请求方法不被允许。比如服务器对某个接口只支持 POST，但你用了 GET 去访问。
```


- 5xx 服务器错误状态码（后端/运维的锅）
表示客户端请求没问题，但服务器内部在执行时崩溃了、超时了或配置错了。
```
500 Internal Server Error：最常见的服务器错误。说明服务器端在执行请求时代码抛出了未捕获的异常/崩溃。

502 Bad Gateway (网关错误)：通常作为网关或代理（如 Nginx）的服务器，从上游服务器（如 Tomcat、Sogou Workflow 程序）收到了一个无效的响应。多半是你的后端程序没挂，但卡死或没启动。

503 Service Unavailable (服务不可用)：服务器暂时无法处理请求。通常是因为服务器超载（高并发扛不住）或正在进行停机维护。

504 Gateway Timeout (网关超时)：网关作为代理，等待上游服务器响应的时间太长，超时了。通常是后端代码里有死循环、慢查询，或者执行耗时任务导致长时间没返回结果。
```
