### LRU算法

```
运用所掌握的数据结构，设计和实现一个  LRU (Least Recently Used，最近最少使用) 缓存机制 。

实现 LRUCache 类：
LRUCache(int capacity) 以正整数作为容量 capacity 初始化 LRU 缓存
int get(int key) 如果关键字 key 存在于缓存中，则返回关键字的值，否则返回 -1 。
void put(int key, int value) 如果关键字已经存在，则变更其数据值；如果关键字不存在，则插入该组「关键字-值」。当缓存容量达到上限时，它应该在写入新数据之前删除最久未使用的数据值，从而为新的数据值留出空间。

class LRUCache {
public:
    LRUCache(int capacity) {}
    
    int get(int key) {}
    
    void put(int key, int value) {}
};
```

思路：
	数据结构：双向链表+哈希表
	双向链表可以快速移动结点，如果有最新插入进来的结点或者最近使用过的结点可以移动到队头，将最近没有使用的结点放在队尾。移动的时间复杂度为O(1)
		双向链表的结点存放key + value
	哈希表：查找的时间复杂度为O(1)可以快速查找所需的值是否在双向链表中
		哈希表存放key+key所对应的位置（物理地址）（这个指向就算是结点移动自己所在链表中的位置也不会改变，因为指向的是物理地址，结点移动只是改变了结点之间的指针指向关系，并不会改变物理位置）

哈希表存的是(key,结点指针) 只在结点出生和死亡时更新  `unordered_map`
双向链表存的是(key,value) 负责在每次被访问时更新前后指针关系 `list`

```
哈希表：
unordered_map <int,list<int,int>::iterator> mp;

```


###### 1. 核心关键：哈希表里到底存 `std::list` 的什么？

前面我们说哈希表里存“节点指针”，那么在标准库中，这个“指针”对应的概念叫做**迭代器（Iterator）**。

所以，我们的哈希表应该这样定义：
```c++
// 它的 Value 是一个指向 list 节点的迭代器
std::unordered_map<int, std::list<std::pair<int, int>>::iterator> mp;
```

_注：`std::list` 里面存的元素必须是 `std::pair<int, int>`（即 key 和 value 绑在一起），原因我们前面聊过，为了淘汰末尾节点时能反向去哈希表里删 key。_

###### 2. 核心技巧：如何做到 $O(1)$ 的移动？（std::list::splice）

如果我们要把链表中间的某个节点挪到队头，直观的想法可能是：先 `erase` 掉这个节点，然后再 `push_front` 到队头。

**但是，绝对不要这样做！**
- 原因：`std::list::erase` 会直接**销毁**这个节点（释放内存）。紧接着你 `push_front` 又会**重新申请**内存。这种频繁的内存申请和释放非常耗时，而且一旦执行了 `erase`，原来指向它的哈希表迭代器就**失效**了，你还得去更新哈希表。
    
为了解决这个问题，C++ 的 `std::list` 提供了一个堪称专为 LRU 设计的神器函数：**`std::list::splice`（粘接）**。

###### `splice` 是怎么工作的？

它可以把当前链表（或者另一个链表）中的某一个节点，**在不销毁、不搬移内存的情况下，直接通过修改指针关系，“斩断”并“粘接”到指定的位置**。

代码写起来极其简单，只需要一行：
```C++
// 把 cache 链表中 it 指向的那个节点，完美移动到 cache 链表的头部（begin() 位置）
cache.splice(cache.begin(), cache, it);
```

- **速度**：完美的 $O(1)$，纯指针操作，没有任何内存开销。
- **最大好处**：由于节点的内存地址没变，**哈希表里存的迭代器依然有效**！你完全不需要去更新哈希表里的指针！

###### 3. 用文字“跑一遍”你的代码逻辑
有了这两个工具，我们现在把算法的伪代码和逻辑在脑海里彻底跑通：
###### 成员变量：

- `int cap;` // 容量
    
- `std::list<std::pair<int, int>> cache;` // 双向链表，挨着 begin() 的最新，挨着 end() 的最老
    
- `std::unordered_map<int, decltype(cache.begin())> mp;` // 哈希表导航仪
    

###### `get(key)` 的逻辑：

1. 去 `mp` 里面找 `key`。
    
2. **没找到**：返回 `-1`。
    
3. **找到了**：
    
    - 通过 `mp[key]` 拿到这个节点在链表里的迭代器 `it`。
        
    - 使用 `cache.splice(cache.begin(), cache, it);` 把他调动到链表最前面。
        
    - 返回这个节点的值 `it->second`。

###### `put(key, value)` 的逻辑：

1. 去 `mp` 里面找 `key`。
    
2. **如果找到了**（说明是更新）：
    
    - 拿到迭代器，把它的 value 改成新值（`it->second = value;`）。
        
    - 使用 `splice` 把他调动到链表最前面。
        
3. **如果没找到**（说明是新插入）：
    
    - **检查容量**：如果 `cache.size() == cap`（慢着，书桌满了！）：
        
        - 找到链表最后那个倒霉蛋：`auto back_node = cache.back();`
            
        - 在哈希表里删掉它的 key：`mp.erase(back_node.first);`
            
        - 在链表里彻底删掉它：`cache.pop_back();`
            
    - **插入新节点**：
        
        - 把新键值对塞到链表头部：`cache.push_front({key, value});`
            
        - 把新节点的迭代器登记到哈希表：`mp[key] = cache.begin();`
